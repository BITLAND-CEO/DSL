# Contributing to DSL

Thank you for helping develop Digital Sign Language.

## Ways to Contribute

You can contribute by:

- proposing a new signal
- improving an existing definition
- identifying ambiguity
- creating examples
- testing machine-readable formats
- improving documentation
- reporting abuse or safety concerns
- translating documentation

## Before Proposing a New Signal

Check whether an existing signal already covers the intended meaning.

A new signal should be:

- clearly distinguishable
- broadly useful
- simple to understand
- language-independent where possible
- unlikely to create harmful ambiguity

## Proposal Process

1. Open a GitHub Issue describing the idea.
2. If appropriate, create a proposal file under `PROPOSALS/`.
3. Discuss the proposal publicly.
4. Revise it when useful.
5. If substantive, conduct a community vote.
6. Record the decision.
7. Update the specification only after approval.

## Pull Requests

Keep changes focused.

A pull request should explain:

- what changed
- why it changed
- whether compatibility is affected
- which proposal or issue it addresses

## Good-Faith Participation

Technical disagreement is expected.

Contributors should focus on definitions, evidence, usability, safety, and interoperability rather than individuals.

See `CODE_OF_CONDUCT.md`.
